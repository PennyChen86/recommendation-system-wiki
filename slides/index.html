01 / USER SIGNALS

AI 真的知道你喜歡什麼？

不完全是。系統通常從可觀察的行為與回饋中，推測你可能感興趣的內容。

★明確回饋

例如你主動評分，直接表達偏好。

Explicit feedback
▶隱含回饋

例如觀看或互動紀錄，可能反映興趣，但不等於真的喜歡。

Implicit feedback
◉內容特徵

影片標籤、類別等資訊，也能幫助模型理解候選項目。

Item features
重點：「你看過」和「你喜歡」不一定是同一件事；模型也可能猜錯。

03 / COLLABORATIVE FILTERING

你沒聽過的歌，
別人可能替你發現。

協同過濾從「人與內容的互動模式」尋找線索，而不一定只靠內容是否相似。

一個簡單的喜好矩陣

聽眾歌 A歌 B歌 C
你💜💜？
聽眾 2💜💜💜
聽眾 3—💜—
可能推薦給你：歌 C

因為聽眾 2 的喜好模式與你相似（教學示意）。

和內容式推薦的差別

不只看歌的類型

協同過濾可利用使用者與項目間的互動關係，發掘看起來不那麼相似的新內容。

真正的模型可能學到 embedding 表示，並非每次都直接尋找「另一個和你一樣的人」。

提示：右邊的矩陣只是幫你理解，不是平台的真實資料。

04 / RECOMMENDATION PIPELINE

推薦清單不是一步完成的。

一種常見推薦架構，會把工作拆成三個階段。

01Candidate Generation

從大量項目中快速挑出較少量、可能符合需求的候選項目。

02Scoring

利用使用者和項目特徵，為候選項目計算分數並排序。

03Re-ranking

最後再調整推薦清單，例如考慮新鮮度與多樣性。

大量影片可能有數百萬個項目
→
少量候選先快速篩選
→
首頁清單排序及調整

這是 Google 教材介紹的常見架構；不代表 Spotify、Netflix、YouTube 在 2026 年完全採用同一流程。

05 / WHEN IT GOES WRONG

越懂你，就越好嗎？

推薦系統的目標設定與最終排序方式，也會影響你看到的世界。

⚠ 只追求點擊，可能變成誘餌標題

如果系統只最佳化點擊率，可能偏好容易吸引點擊、但未必符合使用者長期需求的內容。

R13 / G04
✦ 只有相似內容，可能變得單調

如果推薦清單全部都很像，探索新內容的機會就可能減少。重新排序可以考慮多樣性。

R16–R17 / G05
想一想：你希望推薦系統只給你「最可能點擊」的內容，還是也讓你發現不同風格的新作品？

06 / QUICK QUIZ

換你來當推薦工程師！

先複習兩個剛剛介紹過的方法，再試著判斷：

🎵 內容式推薦（Content-Based）看歌曲本身的曲風、標籤等特徵，找相似的歌曲。
👥 協同過濾（Collaborative Filtering）看不同聽眾的喜好與互動模式，推測可能喜歡的新歌。

你和小美都喜歡歌曲 A、B、C；小美還喜歡歌曲 D。系統因此把 D 推薦給你。這是哪一種推薦方式？

選一個答案，看看你的判斷對不對！

此例以兩位聽眾簡化說明；實際協同過濾不一定直接比較兩個人的清單。至於 Re-ranking（重新排序），是後續調整推薦順序的另一個階段，並非這題比較的推薦方法。
